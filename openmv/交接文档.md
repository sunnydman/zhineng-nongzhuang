# OpenMV 交接文档

当前工作版为 **v010 台架击打判断**。专本组每棵树最多一颗绿果，黄果是保护对象。`T` 表示稳定的视觉候选，`HIT ALLOW` 表示该候选通过台架的击打判断条件。Mega 端的自主作业状态机和触头路径验证仍待整车联调。

| 路径 | 用途 |
|---|---|
| `当前版本/main.py` | 板端入口，采图、色块检测、标注和可选 UART |
| `当前版本/config.py` | 相机模式、LAB、ROI、形状门槛与串口开关 |
| `当前版本/vision.py` | 形状筛选、黄果避让、目标选择和连续确认 |
| `当前版本/protocol.py` | 板端 MV1 发送帧编码 |
| `击打判断/strike_decision.py` | 根据当前帧的视觉观测判断击打资格 |
| `当前版本/camera_test.py` | 独立彩色预览，用于区分采图与识别问题，无需随主程序部署 |
| `当前版本/lab_probe.py` | IDE 单独运行的 LAB 取样工具，显示白框内 LAB 中位数及 10%～90% 分位范围，无需随主程序部署 |
| `历史版本/` | 每个子目录是一套完整的可回退板端源码 |
| `tests/` | 电脑端纯逻辑测试 |

板端有过两套实物组合的调试记录。IDE 曾报告 H7 Plus 配 MT9M114、固件 4.5.5，另一块报告 H7 配 OV5640、固件 4.7.0。记录试验时以 IDE 底栏回读为准。OV5640 曾在手动参数下出现黑画面，切换自动模式后恢复成像。当前默认 `AUTO_CAMERA=True`，`UART_ENABLED=False`。

**部署或回退。** 停止 IDE 正在运行的脚本。选同一版本的 `main.py`、`config.py`、`vision.py`、`protocol.py`。将后三个复制到相机盘根目录。v010 还需要 [击打判断模块](击打判断/README.md)。打开对应的 `main.py` 在 IDE 临时运行，当前版启动日志打印 `OPENMV v010`。

**怎么看画面。** 蓝框为绿果搜索区，黄框为黄色块，绿框为通过形状和黄果检查的候选。红框 `BLOCK` 表示距黄果太近。紫框上的 `EDGE`、`BIG`、`FILL`、`ASPECT`、`SMALL` 分别表示碰到边缘余量、外框过大、填充率不足、太细长、尺寸或像素数不足。`RAW` 是进入形状筛选的绿块数，`G` 是形状筛选后数量，含 `BLOCK`，`Y` 是黄色块数。`WAIT` 表示候选正在确认，`T` 时才画白十字，`N` 表示本帧无可选目标。

**下一轮怎么推进。** 固定相机和补光，先录空树、单浅绿果、浅绿果挂树、同枝一绿一黄。树朝向取 0°、15°、30° 做对照。若浅绿果在蓝框里却经常没有 `RAW`，检查颜色和最小色块门槛。若出现紫框，按拒绝原因核对外框与形状。空树仍被选成 `T` 时，优先用实拍挂果高度和果实尺寸收紧候选。绿果被 `BLOCK` 时记录是黄果还是背景误检。每轮只改一组条件，记录每次过树有没有误选和漏检。

**版本维护。** 每次改检测逻辑前，将 `当前版本/` 的四份板端脚本成套复制到 `历史版本/`，以 `vNNN_当前行为_下一项操作前` 命名，说明来源和验证状态。工作版始终在 `当前版本/` 中维护，在 `main.py` 的启动日志标注版本号，并在 `更新日志.md` 记录改了什么、怎么验证以及回退到哪一包。桌面验证命令为 `python -m unittest discover -s openmv/tests -v`。
