# OpenMV H7 Plus 芒果识别初版

当前工作版为 v010。视觉脚本集中在 [`当前版本/`](当前版本/)，台架击打资格见 [击打判断](击打判断/README.md)。维护入口见 [交接文档](交接文档.md)，回退和截图回放见 [更新日志](更新日志.md)。

视觉流程为 RGB565/QVGA 采图 → LAB 分割 → 绿果掩膜开运算及形状筛选 → 黄果邻近避让 → 最大像素数候选 → 连续帧确认 → 画面与可选 UART 输出。

当前已用平视和仰视现场截图进行离线调参，可直接运行检测。实机性能和帧率待验证。当前程序输出视觉观测。

## 2026年11月23日初值依据

已核对原始规则`比赛资料/附件6：B类“芒果疏果机器人竞技”比赛及评审规则(1).docx`：第二部分规定绿色PETG树高410mm，果实为青绿/奶黄色，正常果长×宽至少55×35mm，小果至多45×30mm；第七部分规定场地和道具尺寸允许误差±5%。专本组以绿果为疏除目标，黄果为保护目标。本版沿用本地专本组方案，未实现硕博组黄色小果分类。

首次试拍建议相机离地约30cm、镜头对准挂果区域、相距约40cm、室内白光补光。这些安装数值是试拍假设，不是规则要求。暂按画面横向覆盖50cm估算，55×35mm果实约35×22px，故设置较宽的面积和长宽比范围；实际视场、透视、果实姿态与遮挡均会改变像素尺寸。规则没有指定LAB、曝光、相机高度或镜头视场，颜色和相机参数是工程试调初值，origin=assumed、roles=calibration/behavior、maturity=candidate。

实际数值以`config.py`为准。默认`AUTO_CAMERA=True`，相机自动调整曝光、增益和白平衡。手动模式初值为曝光10ms、增益6dB、RGB通道增益均0dB。绿果全图搜索，贴真实画面边缘的色块仍由 2px 余量筛掉。绿果采用 9×9 开运算，再按最小100个色块像素、外框180~10000px²、短边至少15px、填充率至少0.40、短长边比至少0.40过滤。黄果全图检测，门槛为40个像素/60px²，并排除高度最多6px、宽至少为高3倍的水平色条。两框最近距离至多18px时标记避让，目标初次确认需要连续3帧。

相对上一版：曝光/增益/RGB由自动收敛值改为固定初值，绿果全图改为明确ROI；绿阈值(20,85,-65,-12,5,65)改为(25,85,-60,-15,10,65)，黄阈值(35,100,-12,25,25,100)改为(45,100,-15,20,20,85)；最小像素80→100、外框120~18000→180~10000、填充率0.30→0.40、短长边比0.35→0.40、黄果外扩15→18px。移除原先阻止T状态输出的标定开关，不把参数修改当成已完成标定。

## 首次运行

1. 用OpenMV IDE连接H7 Plus，记录设备固件版本。代码使用` sensor `、`pyb.UART`接口，当前设备版本兼容性待实机确认。
2. 将`当前版本/`中的`config.py`、`vision.py`、`protocol.py`和`击打判断/`中的`strike_decision.py`放到板载文件系统根目录。用 IDE 打开`当前版本/main.py`临时运行。`camera_test.py`是可在 IDE 单独运行的预览工具。
3. 初次保持`UART_ENABLED=False`，只连接OpenMV进行视觉测试。观察画面与约每秒一次的IDE日志；程序直接给出N/W/T判断，画面带TEST标识。
4. 绿框为绿果候选，黄框为黄果色块，红框/BLOCK为靠近黄果的绿果。待确认目标标记为 WAIT，白十字仅表示本帧的已确认候选。
5. 需要整车联调时再启用UART并实现Mega接收端，先确认其只消费视觉观测，不把稳定候选直接当成摘果许可。

持久自启动时才将主文件保存为板载`main.py`，并验证复位后启动；IDE临时运行与持久启动应分开验证。此次只生成电脑源码，没有写入设备。

## 后续调参顺序

1. 固定安装方向、工作距离、焦距与补光；保持320×240和RGB565。
2. 先用默认自动模式确认成像，启动日志会打印`camera=AUTO`及设备回读值。固定补光后，可用该设备的回读值作手动模式起点，确认成像正常再调LAB。自动模式会随场景调整颜色和亮度，阈值标定时应保持采图条件一致。
3. 先用现有`GREEN_LAB`、`YELLOW_LAB`观察，再用IDE的LAB阈值编辑器修正。用绿色树体、空场景、阴影与反光负样本检查误检。这组初值依据颜色方向选择，并非实物采样结果。
4. 调`MIN_PIXELS`、`MIN_AREA`、`MAX_AREA`、`MIN_FILL`、`MIN_ASPECT`。形状过滤无法保证把同色树体和果实分开；效果不好时需要额外特征或模型。
5. 调`YELLOW_MARGIN_PX`、`STABLE_FRAMES`、`TRACK_DISTANCE_PX`。黄果避让按图像平面外框距离计算。被遮挡或低于最小色块阈值的黄果可能漏检。
6. 记录多光照、多距离、遮挡等条件下的检出率、树体误检、黄果漏检和实际FPS。更改镜头、安装、分辨率、补光或曝光后重新检查阈值与像素参数。

目标选择当前按像素数优先。连续确认检查中心位移和外框面积，目标交叉时仍可能串目标。已确认目标跨一帧漏检恢复时，两框交集还须达到较小框面积的四分之一，否则重新确认三帧。漏检帧为 `N`，没有有效坐标。

## 初版UART合同 MV1（待主控端实现）

生产者是`main.py`，预期消费者是Mega 2560；目前只有发送端和编码测试，没有主控解析器，也未做双端联调。

使用UART3，115200、8位、无校验、1停止位，最大约10Hz。H7 Plus对应P4=TX、P5=RX。未来单向连接时P4接主控所选串口RX并共地；具体主控串口与电平适配待确认。板上“5V供电”标注不是UART逻辑电平说明，接线应按双方硬件规格核对。

ASCII格式，最长128字节，以`$`起始、换行LF结束：

```text
$MV1,seq,capture_ms,state,cx,cy,w,h,pixels,green_count,yellow_count*HH\n
$MV1,1,100,T,10,10,20,20,200,1,0*4D\n
```

这里`\n`表示一个LF字节。`HH`为从`M`到最后一个计数字段的ASCII字节逐字节异或结果，两位大写十六进制，不包含`$`、`*`及换行。

| 字段 | 含义 |
|---|---|
| `seq` | 采图循环序号，0~65535后回绕；非每包加一，限频会跳号，重启归零 |
| `capture_ms` | `time.ticks_ms()`板端采图调用前时间，毫秒；按运行时周期回绕，不是曝光时间；与Mega无时钟同步 |
| `state` | `U`保留作未知状态（当前主循环不发送）；`N`本帧无可选目标（也包括全部被黄果阻挡）；`W`候选尚未连续确认；`T`候选连续稳定；`E`相机/检测/发送异常 |
| `cx,cy` | 仅T有效，图像左上为(0,0)，x向右0~319，y向下0~239，单位像素 |
| `w,h,pixels` | 仅T有效，外框宽/高(1~320/1~240)与命中色块像素数(1~76800) |
| `green_count` | 形状过滤后绿候选数，含BLOCK候选，非已确认果实数量 |
| `yellow_count` | 通过最小面积、像素数和水平色条筛选的黄色色块数，非已确认果实数量 |

非T状态坐标固定为`-1,-1`，尺寸和像素数为0，不沿用旧目标。数据为当前测量，不是摘果指令；T不代表已经标定、分类正确或机构路径可执行。帧格式维持MV1，但接收端不得再假设T意味着已标定。

建议接收端合同：

- 有界接收缓冲128字节，遇`$`重新开始，超长/截断/不完整超过100ms则丢弃。校验、版本、字段数量、枚举、数值范围检查失败即丢弃，不刷新目标有效期。
- 只用T更新候选；其他状态立即使目标失效。300ms未收到新的有效帧时清空目标，不继续使用上一坐标。发送端没有重试或历史帧补发。
- 正常连接按16位序号模差判断先后，差值在1~32767内才接收；重复与乱序丢弃且不刷新有效期。接收端启动或超时后清空序号基线，下一包只建立新基线，再收到更新的T才允许恢复目标。
- 两端未同步时钟，不能用跨板时间差推算帧龄。接收超时只近似衡量新鲜度，链路不能缓存旧帧重放；整车应用前还需实测最大延迟。
- 解析失败、断线、视觉异常不得触发新的摘果动作；链路恢复不应自动恢复执行机构动作。

串口发送短写时程序尝试发送E并终止，不循环重发上一目标。断线或错误帧未送达时依靠接收端超时。
